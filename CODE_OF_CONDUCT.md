# Code of conduct

## The short version

Be decent. Assume the other person is trying to help. Disagree about the work, not the
person.

## Why this project has one at all

This is a site about unemployment, retraining, and money, built largely for people with less
power than the people likely to be reading its source. That shapes what is acceptable here.

Contempt for the people this site is for — as unemployed, as "low-skilled", as immigrants, as
anyone's problem to be managed — is not a difference of opinion to be debated. It is out of
scope for this repository and will be removed.

## Expected

- Take criticism of your code as being about the code.
- Say what you actually think about a technical decision, including that a maintainer's
  decision is wrong. Bluntness is fine. Contempt is not.
- Spanish-language contributions and review are wanted. If your English is imperfect, open the
  issue anyway; if your Spanish is native, this project needs you more than it needs another
  TypeScript reviewer.
- If you disagree with a data-honesty rule in CONTRIBUTING, argue it in an issue. Those rules
  exist for stated reasons and the reasons can be wrong.

## Not acceptable

- Harassment, sustained hostility, or personal attacks.
- Demeaning language about the people this site serves.
- Publishing anyone's private information.
- Sexualised language or imagery.

## Reporting

Email **ckellyreif@gmail.com**. Reports go to the maintainer only, and are not discussed in
public issues.

You will get an acknowledgement within a week. Say what happened, where, and what you would
like done — including nothing, if you are recording it rather than asking for action.

The maintainer will handle it: editing or deleting comments, closing threads, or blocking
accounts. This is a one-maintainer project, so there is no committee and no appeal beyond the
maintainer. Where a report concerns the maintainer's own conduct and you would rather not
raise it with them, GitHub's own reporting is the route that does not run through this
project.

## Scope

Issues, pull requests, commits, and any project space. It also applies where someone
represents the project elsewhere.
