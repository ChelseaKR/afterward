# Internationalization status

i18n status: Applies, and is implemented. English and Spanish have shipped together since
the first release; neither is a translation pass bolted onto the other.

implementation: typed per-locale TypeScript string modules (`web/lib/i18n.ts`,
`web/lib/vocabulary.ts`), with compile-time EN/ES key parity and a test that fails on any
Spanish string left identical to its English original. See ADR 0002 for why this replaces a
catalog directory.

## How it works

- Every UI string lives in typed TypeScript modules (`web/lib/i18n.ts`,
  `web/lib/vocabulary.ts`) keyed by locale. A missing key in either language is a compile
  error, so the site cannot build with a translation gap.
- A test fails if a Spanish string is left identical to its English original, which catches
  untranslated copies the type system cannot see.
- Feed text with no Spanish counterpart in the source data (program names, descriptions,
  provider names) is marked `lang="en"` at every render site via `feedTextLang()`, so a
  Spanish-set screen reader does not read English words with Spanish phonemes. A source-scan
  test (`web/lib/englishFeedText.test.ts`) asserts the guard is present at every render
  site. Details in `docs/wcag-2.2-aaa-conformance.md` (SC 3.1.2).
- Occupation titles are handled per-occupation: 70 of 670 have no published Spanish name and
  are marked accordingly (`occupationTitleLang()`).

## Deliberate divergence from catalog tooling

There is no `locales/` directory and no gettext/ICU extraction step. That is a recorded
decision, not an accident: `docs/adr/0002-bilingual-strings-in-typed-modules.md` explains
why typed modules give this project stronger enforcement (compile-time parity, no silent
English fallback) than catalog files would. The portfolio's mechanical conformance check
looks for a catalog directory and will report a gap here; the gap is in the check's
recognition, not in the site's Spanish.

## Known limits, on the record

- The Spanish has had no native-speaker review. CONTRIBUTING.md names Spanish review as the
  most valuable outside contribution, and the site says so too.
- Source-feed text (program and provider names, descriptions) exists only in English for
  every program; the site marks it rather than machine-translating it.
- Since 2026-08-21 (ADR 0003) a Spanish page can offer an AI translation *on request* for
  exactly the text above and for the 70 occupations Mi Próximo Paso does not cover. It is
  never in the catalogue and never on the page until a reader presses "Traducir con IA"; it
  is labelled AI-translated and unreviewed; the service refuses a translation that changes,
  drops or adds a number; and the English stays in place as the record. None of this is
  native review, and issue #32 stays open. The control is absent from every build that has
  no `NEXT_PUBLIC_ASK_URL`, which is every build until the owner decides to deploy the
  service.
